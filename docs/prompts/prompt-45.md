# Prompt 45 — Premium Automotive App Launch Screen

## Контекст проекта

Это продолжение разработки существующего SaaS-приложения **«AI-администратор для автосервисов»** в репозитории `Autoservise`.

В проекте уже существует рабочий frontend и сформированная дизайн-система:

* Vite
* React
* TypeScript
* Tailwind CSS
* shadcn/ui
* lucide-react
* существующий dark graphite + gold visual system
* рабочая авторизация
* существующий App Shell
* Dashboard
* Conversations
* Clients
* Requests
* Operations
* Appointments
* Service History
* Settings

**Не переделывать существующую дизайн-систему и не ломать существующие экраны.**

---

# Главная задача

Создать **первый экран запуска приложения** — визуальную заставку / welcome screen, которая станет эмоциональным лицом продукта.

Основная идея:

> **Пользователь запускает приложение так, будто запускает автомобиль.**

Это не обычный login screen и не стандартный SaaS splash screen.

Нужно создать короткую кинематографичную сцену:

**темнота → автомобиль проявляется → запуск двигателя → включаются фары → появляется бренд → появляется вход в приложение.**

Общее ощущение:

**Premium Automotive / Dark Luxury / Cinematic / Powerful / Minimal.**

Экран должен производить впечатление дорогого профессионального продукта для современного автосервиса.

---

# Визуальная концепция

Использовать изображение или визуальный фон с **премиальным тёмным автомобилем**.

Предпочтительно:

* чёрный или очень тёмный автомобиль;
* современный спортивный или премиальный автомобиль;
* вид преимущественно спереди или 3/4 спереди;
* автомобиль частично скрыт в темноте;
* глубокий graphite / black background;
* cinematic lighting;
* небольшая атмосферная дымка допустима;
* никакого дешёвого «тюнингового» или агрессивно-гоночного визуала;
* никаких узнаваемых логотипов автомобильных брендов;
* не использовать конкретный автомобильный бренд как часть брендинга приложения.

Автомобиль должен выглядеть **дорого и технологично**, но не кричаще.

---

# Цветовая система

Сохранить существующую дизайн-систему проекта.

Основная атмосфера:

* deep black;
* dark graphite;
* existing graphite surfaces;
* existing gold accent.

Золотой цвет использовать **очень дозированно**.

Важно:

**не превращать экран в золотой.**

Gold должен появляться как:

* тонкий блик;
* небольшая линия;
* акцент бренда;
* hover/focus effect;
* отдельный UI-элемент.

Свет фар должен быть преимущественно:

* холодный белый;
* серебристый;
* слегка голубовато-белый допустим.

Контраст:

**cold headlights + warm gold accent.**

# Сценарий запуска

Создать последовательную анимацию.

## Stage 0 — абсолютная темнота

При открытии страницы пользователь видит практически чёрный экран.

Никакого интерфейса сразу.

Продолжительность примерно:

**0–300 ms**

Можно оставить едва заметный graphite gradient, чтобы экран не выглядел как полностью пустой чёрный прямоугольник.

---

## Stage 1 — автомобиль проявляется

В темноте начинает постепенно проявляться силуэт автомобиля.

Использовать:

* opacity;
* subtle brightness;
* subtle scale;
* возможно лёгкий blur, который постепенно уменьшается.

Автомобиль не должен сразу быть полностью видимым.

Ощущение:

> «Что-то появляется из темноты».

---

# Stage 2 — звук запуска двигателя

Добавить короткий реалистичный звук запуска автомобиля.

Концепция звука:

**deep premium engine start.**

Это должен быть:

* короткий;
* глубокий;
* низкочастотный;
* приглушённый;
* реалистичный;
* премиальный;
* без громкого гоночного рева.

Не нужен звук Formula 1 или суперкара на максимальных оборотах.

Нужен эффект:

> человек сел в дорогой автомобиль, нажал Start, двигатель ожил.

Звук должен быть коротким и восприниматься как **sonic logo продукта**.

---

# ВАЖНО: autoplay

Современные браузеры могут блокировать autoplay со звуком.

Поэтому реализация должна быть корректной.

Не пытаться обходить browser autoplay policies.

Предусмотреть:

* graceful fallback, если звук заблокирован;
* небольшую кнопку Sound / Mute;
* возможность включить звук после первого взаимодействия пользователя;
* отсутствие ошибок в консоли, если autoplay невозможен.

Если браузер разрешает звук — запускать сцену синхронно.

Если браузер запрещает — визуальная анимация должна работать полностью самостоятельно.

**Приложение не должно зависеть от наличия звука.**

---

# Stage 3 — включение фар

Это ключевой момент всей заставки.

После запуска двигателя:

**фары автомобиля постепенно загораются.**

Не мгновенно.

Сначала:

* небольшой свет;
* затем увеличение яркости;
* затем мягкий light bloom;
* свет слегка рассеивается в окружающей атмосфере.

Фары должны визуально «вырезать» автомобиль из темноты.

Это должен быть самый эффектный момент заставки.

Но:

**никаких дешёвых вспышек, strobe или чрезмерного glow.**

Всё должно выглядеть дорого и кинематографично.

---

# Stage 4 — золотой акцент

После включения фар появляется очень тонкий золотой акцент.

Например:

* отражение на кузове;
* тонкая линия;
* небольшой gold glow;
* золотой light streak;
* подсветка элемента интерфейса.

Использовать существующий gold token проекта.

Золотой акцент должен визуально связать cinematic automotive сцену с интерфейсом приложения.

---

# Stage 5 — появление бренда

После запуска автомобиля появляется название продукта.

Пока использовать временный placeholder:

**AUTOSERVISE**

Но архитектуру сделать так, чтобы название можно было легко заменить позже на финальное название продукта.

Название:

* крупное;
* элегантное;
* минималистичное;
* premium typography;
* без чрезмерных эффектов.

Допустимы:

* fade;
* slight upward movement;
* subtle blur-to-sharp transition;
* very subtle gold accent.

Не использовать:

* flashy text animation;
* rotating text;
* bouncing;
* excessive neon;
* gaming-style effects.

---

# Stage 6 — вход в приложение

После появления бренда показать основной CTA.

Например:

**«Войти»**

или

**«Начать работу»**

Кнопка должна соответствовать существующему UI проекта.

Не создавать совершенно новый дизайн кнопки.

Использовать существующие:

* radius;
* typography;
* gold primary;
* hover;
* focus;
* accessibility states.

CTA появляется последним.

---

# Предлагаемый timing

Ориентировочная последовательность:

### 0.0 s

Чёрный экран.

### 0.3 s

Начинает проявляться силуэт автомобиля.

### 0.5–0.8 s

Запускается короткий engine-start sound.

### 0.8–1.1 s

Двигатель «оживает».

### 1.0–1.3 s

Включаются фары.

### 1.3–1.6 s

Появляется subtle gold highlight.

### 1.5–1.9 s

Появляется название.

### 1.9–2.3 s

Появляется CTA.

После этого пользователь может сразу взаимодействовать с приложением.

---

# Очень важный UX-принцип

Не превращать splash screen в обязательную долгую заставку.

Цель:

**wow effect + быстрый доступ к приложению.**

Полная сцена должна занимать примерно **2 секунды**, максимум около **2.5 секунд**.

После завершения:

* пользователь видит полноценный welcome/login state;
* никаких бесконечных animations;
* никаких повторяющихся engine sounds;
* никакого постоянного фонового видео;
* никакой нагрузки на CPU/GPU без необходимости.

---

# Desktop composition

Для desktop можно использовать композицию:

### Левая часть

Бренд / название / короткая фраза / CTA.

### Правая часть

Большой cinematic автомобиль.

Но композиция должна быть адаптивной.

Не привязываться жёстко к 50/50.

Автомобиль может частично выходить за пределы визуального контейнера.

Главное — сохранить ощущение пространства и премиальности.

---

# Mobile composition

На мобильном:

* автомобиль занимает большую верхнюю часть;
* фары остаются визуальным центром;
* бренд располагается ниже или поверх затемнённой области;
* CTA остаётся легко доступным;
* текст не должен перекрываться фарами;
* никакого горизонтального overflow.

---

# Interaction

После завершения intro:

* CTA должен работать сразу;
* Enter должен по возможности запускать основной action;
* keyboard navigation должна работать;
* focus state должен быть видимым;
* screen reader должен получать осмысленное название и CTA;
* `prefers-reduced-motion` должен поддерживаться.

Если пользователь предпочитает reduced motion:

**пропустить cinematic animation или существенно сократить её**, оставив статичный премиальный экран.

---

# Sound control

Добавить ненавязчивый Sound/Mute control.

Он не должен конкурировать с брендом.

Например:

* маленькая иконка speaker;
* минимальный circular button;
* расположение в углу экрана;
* tooltip/accessibility label.

Состояния:

* sound enabled;
* sound muted.

Не делать большой музыкальный player.

---

# Архитектура

Создать отдельный компонент, например:

`AppLaunchScreen`

или аналогичное имя, соответствующее существующей архитектуре проекта.

Разделить:

* visual layer;
* animation state;
* sound handling;
* branding;
* CTA;
* accessibility.

Не смешивать всю логику в одном огромном компоненте.

Сделать легко заменяемыми:

```ts

brandTagline
heroImage

ctaAction
animationDuration
```

Фактический API можно выбрать в соответствии с архитектурой проекта.

Главная задача:

**позже мы должны иметь возможность заменить название, автомобиль, звук и текст без переписывания всей заставки.**

# Assets

Перед реализацией сначала проверь существующую структуру проекта и способ хранения assets.

Не добавляй случайные огромные изображения или тяжёлые видеофайлы.

Если для первого прототипа нужен placeholder asset:

* использовать оптимизированный asset;
* не использовать copyrighted branded car imagery;
* не использовать логотипы производителей;
* желательно использовать generic premium automotive визуал.

Если в проекте уже есть подходящая система assets — использовать её.

---

# Performance

Это критично.

Splash screen не должен:

* значительно увеличивать initial bundle;
* блокировать загрузку приложения;
* вызывать layout shift;
* постоянно грузить GPU;
* запускать тяжёлую анимацию после завершения;
* оставлять timers/listeners после unmount.

После завершения intro:

* очистить timers;
* очистить event listeners;
* остановить audio;
* остановить animation loops;
* не продолжать ненужные эффекты.

---

# Routing / существующее приложение

Сначала исследуй существующую routing/auth архитектуру.

Не ломать:

* login;
* session handling;
* protected routes;
* App Shell;
* existing navigation;
* existing pages.

Определить правильное место для launch screen.

Если пользователь уже авторизован, не заставлять его каждый раз проходить длинную заставку.

Предпочтительно:

* показать launch experience при первом открытии приложения / новой сессии, если это соответствует существующей auth architecture;
* не мешать быстрому возвращению авторизованного пользователя к рабочему интерфейсу.

Не менять auth semantics без необходимости.

---

# Что НЕ делать

Не делать:

* стеклянный generic SaaS dashboard поверх автомобиля;
* neon cyberpunk;
* racing game aesthetic;
* яркие градиенты;
* чрезмерное золото;
* огромный текст на полэкрана;
* постоянно движущуюся машину;
* бесконечный background video;
* громкий engine roar;
* flashy particle effects;
* excessive lens flare;
* spinning loaders;
* стандартный шаблон login page;
* копирование конкретного автомобильного бренда.

---

# Главное визуальное ощущение

После запуска пользователь должен почувствовать:

> **«Я запустил систему так же, как запускают автомобиль».**

Не:

> «Я открыл очередную CRM».

А:

> **«Система ожила и готова к работе».**

Это должен быть фирменный эмоциональный момент продукта.

# Implementation process

Перед изменением кода:

1. Изучи существующую frontend-архитектуру.
2. Найди текущий routing.
3. Найди auth flow.
4. Найди App Shell.
5. Найди существующие design tokens.
6. Найди существующие Button / Dialog / typography / layout компоненты.
7. Проверь структуру assets.
8. Определи минимальный набор новых файлов.

Затем реализуй launch screen.

**Не переписывай существующие компоненты без необходимости.**

# Ключевой критерий готовности

Когда я впервые открываю приложение, я должна увидеть не просто красивую картинку.

Я должна получить ощущение:

**«Я только что запустила автомобиль. Теперь система готова работать».**

Это и есть главная идея этого экрана.
