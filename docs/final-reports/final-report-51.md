## Final Report — Prompt 51: Booking Availability UX

**Итог: PASS.** Во всех трёх формах записи оператор теперь выбирает дату и видит **свободное время, рассчитанное сервером**. Время выбирается кнопкой-слотом до сохранения.

- **Формы:** «Новая запись», «Редактировать» (перенос) в карточке записи, «Создать запись» из заявки.
- **Что учитывает сервер:** рабочие часы, длительность услуги, количество постов (пиковая загрузка Prompt 50), занятость автомобиля, часовой пояс бизнеса.
- **Перенос:** запись не блокирует сама себя.
- **Последнее слово за сервером.** Если слот заняли между выбором и сохранением, сервер, как и прежде, отвечает 409. Форма показывает русское сообщение, заново запрашивает слоты и снимает устаревший выбор.
- **Без изменения схемы и без миграции**, без второго эндпоинта, без новых библиотек. Код AI не менялся.

### 1. Audit result
- **Создание** (`AppointmentsSettingsPage`, карточка «Новая запись»): клиент / автомобиль / услуга, затем дата + «Начало» + «Окончание» вручную (`type=time`). Длительность не подставлялась. Время переводится в UTC через `zonedTimeToUtc` с `Business.timezone`. Ошибка — `err.message`.
- **Перенос** (`AppointmentDetailPanel`, «Редактировать»): та же тройка полей в панели. PATCH всегда отправляет `startAt` / `endAt` и связи.
- **Третья форма создания** — `RequestDetailPanel` («Создать запись» из заявки): та же тройка полей.
- **Бэкенд Prompt 50.**
  - `checkAvailability` — существующий генератор слотов с шагом 30 минут. Учитывает рабочие часы, `Service.durationMinutes`, мощность одним запросом на день и автомобиль; не предлагает уже начавшиеся слоты. По HTTP он **не был доступен**: его вызывал только инструмент AI.
  - `GET /api/appointments/availability` умел проверять **один** интервал.
  - Генератор не умел исключать переносимую запись.
- **Длительность:** каноническая для слота — `Service.durationMinutes`, как в генераторе. У сохранённой записи длительность задаёт её `endAt`.
- **Фронтенд-тестов** (компонентных) в проекте нет, есть только Vitest для Node.

### 3. Existing architecture reused
- **Расчёт слотов** — существующий `checkAvailability` (Prompt 10 + мощность Prompt 50); второго генератора нет.
- **Проверка ручного интервала** — `checkIntervalAvailability` (Prompt 50).
- **Финальная проверка** — неизменные `createAppointment` / `updateAppointment` с блокировкой бизнеса.
- **Время** — `zonedTimeToUtc` / `utcToZonedParts` (клиент) и `businessLocalToUtc` (сервер).
- **UI** — `Button` / `Input` / `Label`, `lucide-react`.

### 4. API changes (additive, backward compatible)
`GET /api/appointments/availability` — тот же эндпоинт, новый **режим дня**:

- **Запрос:** `?date=YYYY-MM-DD&serviceId=…` (+ `vehicleId`, `excludeAppointmentId`). Вместе с `startAt` → 400.
- **Ответ:** `{ availability: { date, timezone, slots: [{ startAt, endAt, localStart, localEnd }] } }`.
- **Интервальный режим** (`startAt`) не изменился.

Изменения в сервисе:
- `checkAvailability` принимает `excludeAppointmentId`. Переносимая запись не учитывается ни в загрузке постов, ни в конфликте автомобиля.
- Проверки автомобиля по слотам теперь идут **параллельно**, а не одна за другой, в том же порядке и тем же `findConflict`. Инструмент AI вызывает этот же генератор без исключения, поэтому его поведение не изменилось.
- `excludeAppointmentId` проверяется по тенанту и бизнесу в **обоих** режимах: чужой или неизвестный id → 404, никогда не игнорируется молча.

### 5. Create Appointment behavior
1. Клиент → автомобиль → услуга → дата.
2. Появляются слоты для этой услуги и этого автомобиля.
3. Клик по слоту ставит начало и конец (длительность услуги).
4. «Сохранить» отправляет прежний `POST /api/appointments`.

При смене даты, услуги или автомобиля время **сразу снимается**, слоты запрашиваются заново. Время возвращается, только если сервер снова предлагает слот с тем же началом (§5–§7). Окна, в котором можно сохранить устаревшее время, нет.

### 6. Reschedule behavior
- **Открытие:** текущие дата и время **сохраняются** (`preserveInitialTime`). Слоты запрашиваются с `excludeAppointmentId`, поэтому текущий слот подсвечен как свободный, даже если все посты заняты.
  - Если текущее время не совпадает со стандартным слотом (нестандартная длительность), оно показано как «Текущее время» и не сбрасывается, пока оператор ничего не меняет.
- **Смена даты, услуги или автомобиля** — те же правила, что при создании. Выбор слота задаёт новые начало и конец.
- **«Сохранить»** идёт через прежний `PATCH /api/appointments/:id` — переносится **та же** запись.
- **Завершённые / отменённые / неявки** перенести нельзя (правило сервера). Для них время показано только для чтения: «перенос недоступен для этого статуса».

### 7. Capacity handling
Семантика Prompt 50 не изменилась, расчёт только на сервере.

- **Пиковая одновременность:** при 2 постах и записи 10:00–11:00 слот 10:00 остаётся доступным. При A 10:00–11:00 и B 10:30–11:30 слоты 10:00 и 10:30 скрыты, 09:00 и 11:00 доступны (тест + браузер).
- Отменённые, завершённые и неявки слот не скрывают (тест).

### 8. Vehicle conflict handling
Когда выбран автомобиль, слоты, где у **этого** автомобиля уже есть запись, не предлагаются, даже если посты свободны; другому автомобилю они доступны (тест). Логика — серверный `findConflict`; в React её нет.

### 9. Business hours / timezone handling
- **Часы и длительность:** первый слот — открытие, последний — тот, что заканчивается к закрытию. При 60 минутах и закрытии в 18:00 последний слот 17:00, а 17:30 не предлагается; при 90 минутах последний слот 16:30 (тесты).
- **Выходной** → пустой список (тест + браузер). **Прошедшая дата** → пусто, потому что уже начавшиеся слоты не предлагаются.
- **Дата** — календарный день **в часовом поясе бизнеса**; `localStart` / `localEnd` — время бизнеса.
- **Тест Asia/Kamchatka (UTC+12):** слот понедельника 09:00 = воскресенье 21:00Z.
- **Браузерная проверка с часовым поясом браузера America/New_York:** слоты начинаются в 08:00 (открытие бизнеса в Europe/Moscow). Запись на «10:00» сохранена как `07:00Z` = 10:00 MSK. Часовой пояс браузера нигде не используется.

### 10. Race-condition behavior
Блокировка Prompt 50 не изменялась: показ слота — подсказка, а не гарантия.

Если слот заняли до «Сохранить»:
1. Сервер отвечает `409 CAPACITY_EXCEEDED` (или `APPOINTMENT_CONFLICT`).
2. Форма показывает «На выбранное время уже нет свободных постов. Выберите другое время.» (или «У этого автомобиля уже есть запись на это время…»).
3. Слоты запрашиваются заново; занятый слот исчезает, выбор снимается.

Это проверено и тестом, и в браузере на настоящей гонке: пока форма открыта, другой запрос через API занимает тот же слот. Сырой `conflictingAppointmentId` больше не выводится в форме как «ошибка поля».

### 11. Security / tenant isolation
- Маршрут защищён `requireAuth` (без сессии → 401, тест). Бизнес, часовой пояс и мощность берутся из сессии.
- `serviceId` / `vehicleId` / `excludeAppointmentId` чужого тенанта → 404 (тест). Чужие записи не влияют на свои слоты и не видны (тест).
- Исключение снимает из подсчёта только одну **свою** запись. Финальная проверка при сохранении не ослаблена.

### 19. Remaining gaps NOT solved by Prompt 51
1. **Перенос по слоту применяет стандартную длительность услуги.** Нестандартную длительность сохраняет «Указать время вручную» (с проверкой сервера) или если ничего не менять. Отдельного параметра «длительность» у слотов нет: второй модели длительности не вводилось.
2. **Редактирование завершённой / отменённой записи через форму** по-прежнему упирается в сервер: форма всегда отправляет время и связи, а сервер запрещает их менять у терминальной записи. Так было и до Prompt 51; здесь время терминальной записи лишь показано только для чтения.
3. **Компонентных тестов нет** (как и раньше в проекте). Интерактивные состояния проверены в браузере, а чистая логика покрыта Vitest.
4. **Сетка — существующие 30 минут.** Задать шаг в настройках нельзя.
5. **AI:** код не менялся. Инструмент `check_availability` получает тот же генератор (без исключения записи). Сопоставление `CAPACITY_EXCEEDED` в ошибках инструментов AI по-прежнему остаётся задачей подключения AI к записи (см. отчёт Prompt 50).
6. **Без календаря, мастеров, отдельных постов, напоминаний и интеграций** — вне объёма.
7. **Тестовые данные** «Проверка P50 / P51» (отменённые записи) остаются в тестовом тенанте.
