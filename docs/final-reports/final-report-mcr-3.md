## Final Report — MCR-3: Pricing & Business Location Foundation

У цены услуги теперь **одна** серверная интерпретация: фиксированная, «от»,
диапазон или «цены нет». К цене можно добавить условия и явный флаг «нужен
осмотр». У бизнеса появилась безопасная ссылка на карту рядом с адресом.

AI получает всё это как явные факты, а не как сырые nullable-числа.
AI-контракт запрещает придумывать цены, адреса и маршруты, а данные услуги
главнее текстов Knowledge. Сообщения не отправляются; MCR-4 не начат.

### 2. Existing pricing audit (по реальному коду и данным)

- **`Service`:** `priceFrom` / `priceTo` (Decimal 10,2, nullable), `currency`
  (снимок валюты бизнеса при создании), `durationMinutes` (обязательно),
  `isActive`, `name` / `description`.
- **Фактическая семантика была неявной и разной в трёх местах:**
  - правило 17 промпта: оба значения — диапазон, только `priceFrom` — «от»;
  - mock-провайдер: собственная `formatPriceRange`;
  - UI настроек: клиентская `formatPriceRange`, которая **теряла «от»**
    (`priceFrom` без `priceTo` показывалась как «4 800 ₽», то есть как
    фиксированная цена) и показывала `priceTo` без `priceFrom` как
    фиксированную цену.
- **Валидация** допускала «только `priceTo`» (смысл «до X» нигде не определён).
- **Данные dev-базы:** 7 услуг, все с корректным диапазоном в RUB; «только
  до» — 0 строк.
- **Бизнес:** текстовый `address` (у 0 из 7 заполнен), `phone`, `email`,
  `website`. Координат и ссылки на карту нет. В AI-контексте уже были name,
  phone, email, address и часы работы.

### 4. Canonical pricing semantics

`src/server/domain/pricing.ts` — `describeServicePricing({ priceFrom, priceTo, currency })`:

| priceFrom | priceTo | type | Пример |
|---|---|---|---|
| X | X | FIXED | «15 000 ₸» |
| X | null | FROM | «от 40 000 ₸» |
| X | Y > X | RANGE | «10 000–20 000 ₸» |
| null | null | UNAVAILABLE | без текста и числа |
| null | Y / Y < X / отрицательное / не число | **UNAVAILABLE** | некорректные данные никогда не становятся обещанием клиенту |

Возвращает `{ type, min, max, currency, formatted }`. Используют **только** её:
- DTO услуги (настройки);
- AI-контекст;
- mock-провайдер.

Клиентская `formatPriceRange`, которая искажала «от», удалена вместе с тремя
её тестами.

### 5. Price formatter

- Тот же модуль. Группировка разрядов `ru-RU`; копейки и тиыны — только если
  не нули (`1 500,50`).
- **Символ валюты** — свой для каждой: `₸`, `₽`, `$`, `€`. Валюта не зашита в
  KZT; для неизвестной показывается ISO-код.
- **Форматы:** FIXED «15 000 ₸», FROM «от 40 000 ₸», RANGE «40 000–60 000 ₸»,
  UNAVAILABLE → `null` (числа нет).
- Форматирование отделено от AI: модель получает готовый `pricing.formatted`.

### 6. priceNote behavior

- **Что это:** условие цены, заданное бизнесом («за одну деталь», «без
  запчастей»). Обычный текст, не HTML.
- **Валидация:** обрезка пробелов, `""` → null, не более 300 (Zod плюс CHECK в БД).
- **Не источник числа:** число берётся только из `priceFrom` / `priceTo`.
- **Куда попадает:** DTO, AI-контекст, список услуг в настройках («Условия
  цены: …»).
- **Ответ mock-провайдера** передаёт условие как есть, без двойной точки.

### 7. requiresInspection behavior

- **Задаётся явно**, по умолчанию `false`: существующие услуги **не** стали
  внезапно требовать осмотра.
- **Не выводится из типа цены:** диапазон или «от» ≠ осмотр (проверено тестом).
- **`true`:** AI обязан сказать «точная стоимость подтверждается после осмотра».
- **`false`:** AI не должен утверждать, что осмотр обязателен.

### 8. Business location design

- **Что хранится:** существующий `address` (текст для людей) плюс новый
  необязательный `locationUrl` — ссылка, которую бизнес задаёт сам (2ГИС,
  Яндекс Карты, Google Maps или любой другой сервис).
- **Без привязки к провайдеру:** Maps API, геокодирования, SDK и маршрутов нет.
- **Остальные контакты** (`name`, `phone`, `email`, `website`, часы работы) уже
  были авторитетными. Они не дублируются, `locationUrl` просто добавлен в
  AI-контекст рядом с ними.

### 9. Location URL security

`isSafeLocationUrl`:
- абсолютный URL с хостом;
- протокол **только** `https:` или `http:`; `javascript:`, `data:`, `ftp:` и
  относительные ссылки отклоняются;
- без пробелов, не длиннее 2000;
- `""` → null (поле очищается).

Дублируется CHECK в БД. Сервер ссылку **не загружает**, не делает предпросмотр
и не рендерит как HTML; в UI это просто значение `<input type="url">`.

### 10. Knowledge vs structured-data responsibility

| Источник | Владеет |
|---|---|
| Структурированная Service | название, активность, числовая цена, тип цены, длительность, условия цены, флаг осмотра |
| Структурированный Business | название, адрес, ссылка на карту, часы работы, телефон и email |
| Knowledge | только пояснения: гарантия, оплата, подготовка, FAQ, ограничения, не смоделированные структурно |

**Правило:** если Knowledge называет одну цену, а Service другую — верна
Service. Это правило 24 промпта и §7 `AI_BEHAVIOR_CONTRACT.md`. Тест
подтверждает, что при «5 000 ₸ по акции» в Knowledge ответ остаётся «от 40 000 ₸».

### 11. AI context changes

**Каждая услуга:**
- `pricing { type, formatted, min, max }`;
- `priceNote`, `requiresInspection`;
- `currency`, `durationMinutes`.

Сырые `priceFrom` / `priceTo` из контекста **убраны**: модели больше нечего

**Бизнес:** добавлен `locationUrl` к уже бывшим `name`, `address`, `phone`,

### 12. AI safety contract changes

`promptBuilder.ts`:
- **Правило 6:** единственный источник цены — `services[].pricing`; никаких
  цен из Knowledge, правил или общих знаний; никаких скидок.
- **Правило 17 (переписано):**
  - FIXED — ровно эта цена;
  - FROM — только «от …», без придуманной верхней границы и не как
    окончательная;
  - RANGE — диапазон;
  - UNAVAILABLE — «цену уточнит мастер или администратор» без цифр;
  - «от» и диапазон — это ориентир;
  - `requiresInspection` — правило из §7;
  - `priceNote` передаётся без искажений.
- **Правило 23:** адрес и ссылка только из `business.address` /
  `business.locationUrl`; никаких придуманных адресов, ссылок, ориентиров или
  маршрутов.
- **Правило 24:** структурированные данные главнее текста; Knowledge — не
  источник цен.
- **Правило 25:** сначала полезный ответ, потом один-два нужных вопроса, без
  анкет.

Сохранены правила про диагноз (4, 16) и про бронирование только по реальной
доступности (8–10, Prompt 56). Правила входят в базовый промпт, поэтому
действуют и в режимах draft / qualify (проверено тестом). `AI_BEHAVIOR_CONTRACT.md`
дополнен §7, §7.1 (локация) и §7.2 («сначала польза»).

### 25. Known limitations

- **Цена от класса автомобиля не моделируется** (BMW X5 и хэтчбек — одна цена
  «от»). Ответ «зависит от состояния / после осмотра» плюс передача человеку —
  ожидаемое поведение.
- **Нет «цены до X» без нижней границы** (сознательно запрещено).
- **Ссылка на карту не проверяется** на то, что это действительно карта:
  только формат http(s).
- **Нет отправки геоточки** (это свойство канала; исследование R0-A).
- **Правила 23–25 работают через промпт.** Реальная модель OpenAI не
  проверялась (ключа нет); поведение доказано на mock-провайдере и в контракте.
- **Мультивалютный бизнес:** валюта услуги — снимок при создании, как и раньше.
- **`prisma format --check`** — старая проблема (§21).
- **Не реализовано:** MCR-4+, отправка сообщений, WhatsApp, SMS, автоответы.

### 26. Readiness for MCR-4

**Вопрос:** CallInteraction в состоянии `READY`, клиент позже пишет «Нужно
покрасить капот BMW X5. Сколько стоит и где вы находитесь?» — хватит ли
авторитетного контекста, чтобы ответить, ничего не выдумывая?

| Пункт | Ответ | Пояснение |
|---|---|---|
| Есть ли такая услуга | **YES** | Активные услуги с названиями в контексте; правило 7 запрещает несуществующие. Сопоставление «покрасить капот» с «Покраска капота» делает модель по названию; детерминированного каталога синонимов нет. |
| Фиксированная / от / диапазон / нет цены | **YES** | Явные `pricing.type` и `pricing.formatted` из одной серверной функции; UNAVAILABLE без числа. |
| Условия цены | **YES** | `priceNote`, если бизнес его задал. |
| Нужен ли осмотр | **YES** | Явный `requiresInspection`, никогда не выводится из типа цены. |
| Длительность | **YES** | `durationMinutes` (обязательное поле услуги). |
| Адрес бизнеса | **PARTIAL** | Поле есть и попадает в контекст, но у текущих бизнесов не заполнено. Без адреса AI честно передаёт вопрос администратору (правило 23). |
| Ссылка на карту | **PARTIAL** | Поле есть и безопасно, но необязательное, сейчас ни у кого не задано. Без ссылки AI её не выдумывает. |
| Часы работы | **YES** | `workingHours` и `currentDateTime` в контексте. Исключений по праздникам нет (известный пробел P1). |
| Реальные свободные слоты | **YES** | Через существующие `check_availability` (P10 / P51), вызов которого разрешён в черновике. Обещать время без этого вызова запрещено (правило 8). Сама запись — подтверждение оператором (P56). |
| Конкретный автомобиль (BMW X5) | **PARTIAL** | Цена от авто не зависит; данные авто из сообщения — непроверенные слова клиента (правило 22), пока оператор не сохранит авто (P54). |

**Итог:** для ответа «услуга есть, от X, условия, после осмотра, длительность,
адрес / ссылка (если заданы), часы, свободное время» данных достаточно, и
придумывать ничего не нужно.

Чтобы ответ состоялся **автоматически** после пропущенного звонка, MCR-4 / MCR-5
должны добавить:
- канал и первое сообщение;
- автоответ;
- захват `READY`-звонка в работу.

Владельцам нужно заполнить адрес и ссылку в настройках.
